# Semantic retrieval

1. In Settings → Models, download **BGE Large English v1.5**. The existing model manager verifies pinned SHA-256 hashes and supports cancellation/resume. Weights are never downloaded by the inference worker.
2. Enable **Semantic indexing (BGE Large + LanceDB)** under Search indexing and apply settings. Choose Index now for an immediate pass; otherwise the normal Adaptive/Background schedule applies. Manual mode requires Index now.
3. In Search → Indexed, select **Semantic (BGE + LanceDB)**. Keyword/Tantivy and Grep remain available.

The model uses the pinned BAAI revision `d4aa6901d3a41ba39fb536a557fa166f842b0e09`, local Hugging Face Transformers CLS pooling and normalized 1024-dimensional vectors. Short queries receive the model's retrieval instruction. Evidence text never leaves the machine. First use provisions a dedicated uv environment with pinned Torch, Transformers, PyArrow and LanceDB dependencies; this dependency installation requires connectivity. Inference is offline. NVIDIA systems use CUDA with FP16 weights, batches of 32 and automatic batch reduction on CUDA OOM. A detected NVIDIA GPU with an unusable CUDA runtime produces an explicit error instead of silently indexing on CPU. Other systems use CPU batches of eight and four Torch threads. Options shows the actual embedding device, checked-record counts and the current loading, embedding, writing, compaction or search-index phase.

Each case stores LanceDB data, a reconciliation ledger and saved progress under `<case database>.tantivy-v1/vectors-bge-v1`. Changing/closing cases releases the model worker. Models are shared on disk across cases; vectors and checkpoints are case-specific. Closing/reopening reuses existing embeddings rather than generating them again.

The background vector pass reads a bounded stream of live, committed Tantivy chunks. It covers the same eligible filesystem metadata, artifact rows and text content as that index, including its binary/file-size exclusions. Complete artifact JSON is rendered into field-labeled text without changing original parser data. Partial JSON remains recorded text. The model tokenizer splits passages with overlap and checks actual input lengths, including special tokens, before inference. Inputs exceeding the model limit fail explicitly rather than being silently truncated.

LanceDB stores the original group/artifact reference, source path, original indexed body, readable passage text, token start/end offsets within the readable parent, model revision and vector. Token offsets refer to the rendered text, not byte offsets in original evidence. Readable search previews reuse the existing indexed-result presentation. Similarity distances are ranking signals, not probabilities or proof of identity.

Lone surrogate characters in malformed parser text or paths are shown as explicit `\udc9d`-style escapes at UTF-8 storage and model boundaries. Valid Unicode and the original indexed JSON are preserved; case evidence is never rewritten. Fingerprints use the original code points, so unchanged records still reuse their embeddings after a restart.

Fingerprints skip unchanged parents before tokenization/inference. The native worker sends at most 128 records or approximately 512 KiB of body text per request. Changed parents are replaced as bounded batches; Lance writes complete before SQLite checkpoints so interrupted batches replay safely. An unchanged batch does not scan Lance for a row count. Deletions are swept only after an entire source snapshot completes. Fragment maintenance runs at the beginning/end of a pass and after 128 changed writes when at least 128 fragments exist, preventing tiny appends from slowing down a long first pass. Collections of at least 4096 passages build a cosine IVF-PQ index; queries refine ANN candidates and include newer unindexed records. Semantic results are limited to the top 100 passages. A completed Tantivy snapshot fingerprint skips the vector pass entirely when nothing changed; interrupted generations must reconcile before a snapshot can be marked complete.

To benchmark an existing case with its downloaded model, run `scripts/benchmarks/vector_index.py` using the BGE environment's Python and provide `--case`, `--model` and `--output`. It requires CUDA, reads a bounded sample from the saved case vectors, and benchmarks the previous and current batch sizes in disposable indexes beside the output file. The case index is read only, evidence text is never printed, and the summary contains timings and device information. This measures the sampled workload rather than predicting throughput for every artifact type.

This provides local vector retrieval. The [case chat](case-chat.md) layer adds Qwen3-8B answers with evidence references. Vector retrieval does not replace structured SQLite correlation or CLIP image embeddings. Integration tests exercise real LanceDB with synthetic vectors and the actual BGE tokenizer; GPU throughput and full-model retrieval quality require downloading the model and evaluating real case queries.

References: [BGE model card](https://huggingface.co/BAAI/bge-large-en-v1.5), [LanceDB Python API](https://lancedb.github.io/lancedb/python/python/).
