# Map files

Add KML, GPX, or GeoJSON files (or a directory containing them) as a datasource, then run the built-in **Map Files** plugin. Open **Map** in the workspace sidebar to view the saved layers.

The Rust parser supports KML points, lines, polygons with holes, MultiGeometry and gx:Track; GPX waypoints, routes and segmented tracks; and all GeoJSON geometry types, Features and FeatureCollections. Separate GPX track segments remain separate. Single-position GPX segments are retained as points. Coordinates use WGS84 longitude, latitude and optional elevation in meters.

The Map workspace uses the same MapLibre engine, streets/satellite basemaps and basemap image resolver as the Drone page. Toggle layers, fit all visible data or a single layer, search features, and select geometry on the map to inspect properties and source paths. Evidence descriptions are displayed as text. If the basemap is unavailable, geometry remains visible on a local background.

Layers are on the left and feature browsing and details are on the right. Both sidebars can be resized or closed with their close buttons. Use **Layers** and **Features** in the toolbar to reopen them. Selecting a feature on the map opens the feature sidebar automatically.

**Export HTML** saves the visible layers after applying the current date and time filters to a single interactive HTML file. The snapshot includes the selected timezone and filter settings. Display conversions are stored separately from the original timestamp values. Feature data, MapLibre, its worker, styling and license are embedded, so the file opens without Cultivator or a CDN. The viewer supports layer toggles, feature details, fit and zoom controls. Street/satellite imagery requires internet access; choose **Offline background** to view embedded points and geometry without network access. Source evidence and internal case files cannot be overwritten by the export.

Choose **Settings → Date and time → Display timezone** to save an IANA timezone or use the system timezone. The default is UTC. Known UTC/offset timestamps display in this zone, with the applicable UTC offset and daylight saving time. Map features, typed artifact timestamp columns, timeline display, file/media modified dates, case dates and plugin history use the preference automatically. Original evidence and unspecified-zone timestamps are preserved. Timeline date filters remain explicitly labeled UTC.

Use **From** and **To** to filter visible layers by date; both boundary days are included, and either end can be left open. **Daily time range** restricts the time of day within those dates, or across all dates if none are selected. An earlier end time crosses midnight (22:00–02:00 includes late evening and early morning on each selected calendar day). The complete ending minute or second is included. Map dates and times use the saved timezone; unspecified timestamps keep their recorded clock. Repeated DST hours match either occurrence, while skipped clocks do not match. Tracks and features with start/end times match when any part of their recorded range overlaps the filter; their full geometry is retained. Features without recognized timestamps are excluded during filtering unless **Include missing dates/times** is checked. Date-only features need that option when a time filter is active, and must still match the selected date range. **Clear filters** restores all features. Filtering uses saved results and does not require running the parser again.

Names, descriptions, properties, elevations, original feature IDs and available track timestamps are retained in case artifacts. KML styles are preserved as references; remote KML links and overlays are not downloaded. Non-WGS84 GeoJSON CRS declarations are rejected rather than plotted with incorrect coordinates.

Invalid features are reported in the layer warnings, and invalid files are reported in the plugin log while other files continue. A run where every input fails preserves the previous results. Limits are 64 MiB per source, 100,000 features and 500,000 positions per layer. Source evidence is not modified, and disk-image imports materialize only the selected map files.
